## 0. Root cause of the loop (read this first — it changes everything below)

The PR body states: *"Effective default enablement is unchanged; U9 owns the default flip."*
`templates/WORKFLOW-config.yaml:30-32` ships `pathway_enforcement.mode: off` and documents `off` as
**non-enforcing**. **But no shipped code reads `pathway_enforcement.mode`.** All three transports
(`scripts/idc_path_gate.py`, `scripts/idc_git_path_gate.py`,
`scripts/hooks/idc_interlock_gate.py` + `hooks/hooks.json`) hard-deny **unconditionally**.

So the PR claims "nothing is enforced by default" while the code enforces everything, everywhere, on
the next `/idc:update`. Every reviewer then correctly finds that the real lifecycle — build
worktrees, work branches, Pi, Codex, and ordinary human `git commit` — is bricked. The three fix
rounds only closed shell-bypass *instances* (round 1 diagnostics, round 2 aliases, round 3 opaque
shells) and never touched the lifecycle, so each round the reviewers find the *next* instance. **This
is unwinnable by patching bypasses.**

**The fix is to make the code match its own claim:** the Path Gate becomes a real, shared *core*, but
its **enforcement posture is gated on `pathway_enforcement.mode`**, default `off` = observe-only
(compute + log, never block). Hard enforcement lives behind `mode: controlled`, which is opt-in and
whose full lifecycle producers (per-worktree/branch authorization, Pi/Codex minting, sanctioned merge
helper) are **explicitly deferred to U8/U9 — the units the spec already assigns them to.** That is
the honest scope of U4.

This collapses 5 of the 8 Codex blockers to non-blocking-for-default and ends the churn, because the
default experience stops mutating anyone's repo.

## 1. THE ONE DECISION (recommended answer baked in)

## 2. Workstream A — Mode gating (closes Blocker 1; de-fangs Blockers 2,3,4,5,8 + Majors 3,4,10)

Add ONE shared reader and make every transport consult it.

- **A1. `pathway_mode(repo) -> "off" | "controlled" | "app-locked"` in `scripts/idc_path_gate.py`.**
  Locate the scaffolded pathway config (the `pathway_enforcement:` block; it lands from
  `templates/WORKFLOW-config.yaml`). Parse `mode`. **Absent/unreadable/unknown ⇒ return `off`**
  (fail to non-enforcing, matching "non-enforcing until enablement lands"). No YAML dependency —
  a minimal line scan is fine and matches the repo's existing config-reading style.

- **A2. `evaluate_request()` posture.** Keep computing the full allow/deny decision. Add a top-level
  wrapper the transports call: in `off`, a would-be deny is returned as
  `{"allowed": true, "observe": <original reason>}` (never blocks); in `controlled`/`app-locked`,
  behavior is today's hard deny. Do NOT weaken the decision engine itself — only the posture applied
  to it. `IDC_HOOKS_OBSERVE_ONLY=1` stays an independent override that forces observe in any mode.

- **A3. Claude transport** (`scripts/hooks/idc_interlock_gate.py` `_gate`): in `off`, emit the warn
  path (stderr additionalContext), never `permissionDecision:deny`. This literally restores the
  pre-U4 warn behavior for the default and keeps the deny for `controlled`.

- **A4. Git hooks** (`scripts/idc_git_path_gate.py` `cmd_pre_commit`/`cmd_pre_push`): compute + print
  the reason to stderr, but **exit 0 in `off`**; exit non-zero only in `controlled`/`app-locked`.
  Keep install/verify unconditional (cheap, idempotent) so `verify-hooks` stays meaningful across
  mode flips.

- **A5. Pi transport** (`runtime/pi/extensions/idc-role-harness.ts` `evaluateSharedPathGate` and the
  two `enforceSharedPathGatePath` call sites + `denyThroughSharedPathGate`): when the shared core
  returns `observe`, treat as allow. The core already knows the mode via A1, so Pi inherits it for
  free through the JSON `observe` field — no separate TS mode reader needed.

**Acceptance (red-when-broken):**
- New `tests/smoke/governance/path-gate-mode.sh`: in a `mode: off` repo, every Write/Edit/raw-gh/git
  case that `path-gate-interlock-denial.sh` denies must **allow (empty decision) and print an observe
  line**; flip the same repo to `mode: controlled` and each must hard-deny. Neuter A1 (force
  `controlled`) ⇒ the off-half goes red. Neuter the deny ⇒ the controlled-half goes red.
- The existing governance suites (`path-gate-*.sh`, `interlock-*.sh`, `phase8-pi-*`) are rewritten to
  set `mode: controlled` explicitly in their fixtures (they already test the deny posture). This is
  the honest home for those assertions.

## 3. Workstream B — Unconditional correctness fixes (right in EVERY mode; these kill the bypass-churn class)

These are correct regardless of posture, so land them now so `controlled` isn't shipped broken. **The
single most important one is B1 — it converts the analyzer from "enumerate safe forms, allow the
rest" (which regenerates a new bypass every round) to "unresolvable ⇒ fail closed."**

- **B1. Top-level shell-variable bypass → fail closed** (Codex Blocker 7; Claude finding 5).
  `scripts/hooks/idc_interlock_gate.py`: `_analyze_direct_segments` / `_repo_candidate_path` silently
  drop `$`/backtick-bearing tokens (`:1270-1285`), and `_git_no_verify_hit` (`:1523-1529`) matches
  only literal `--no-verify`/`-n`. A `$`-bearing token in **a mutation-target position OR a
  policy-sensitive git-flag position** must set `deny_reason` (opaque), not be skipped. Reuse the
  round-3 `_has_shell_expansion` treatment that nested payloads already get.
  *Test:* extend `path-gate-git-backstops.sh` `deny_or_exploit` with `T=TRACKER.md; cp src/app.ts $T`
  and `G=--no-verify; git commit $G -m x` (the exact Claude live-probe escape). Both must deny.

- **B2. Multi-commit push-history gap** (Blocker 6; Claude finding 4). `_collect_pre_push_paths` uses
  `diff-tree` on the local tip only for a new ref. Union **all newly-reachable commits**:
  `git rev-list <local_sha> --not --remotes` (fall back to the tip if that errors), collect names
  from each.
  *Test:* push a new branch whose lower commit mutates `TRACKER.md` and whose tip is innocent ⇒
  pre-push must block (assert the remote never received `ticket: SMUGGLED`).

- **B3. Pre-push stdin replay to the chained hook** (Major 7). `cmd_pre_push` consumes all pushed-ref
  records, then the wrapper execs the original hook on EOF — the original gets empty stdin. Buffer
  stdin once, gate on it, then replay the identical bytes to the chained hook.
  *Test:* install with a pre-existing pre-push hook that reads stdin and writes it to a file; push;
  assert the file received the exact ref records.

- **B4. Staged/pushed deletions** (Major 8). `_collect_pre_commit_paths` uses
  `--diff-filter=ACMRTUXB` (omits `D`). Add `D`.
  *Test:* a deletion-only commit of `TRACKER.md` must be evaluated (denied in `controlled`).

- **B5. Out-of-repo paths = out of jurisdiction, not invalid** (Major 1; Claude finding 3).
  `scripts/idc_path_gate.py` `_normalize_repo_rel` / `evaluate_request` turn an outside path into an
  invalid-request **deny**. Change: a path resolving outside the repo root ⇒ **allow** ("outside this
  gate's jurisdiction — deferred to runtime role/secret policy"). This restores Claude `/tmp` scratch
  writes and Pi's declared scratch roots.
  *Test:* `Write /tmp/idc-note.md` from a governed session ⇒ allow.

- **B6. Case-insensitive protected-path match** (Major 12). `_is_protected_machine_path` uses
  `fnmatchcase`. On macOS/APFS a case variant (`tracker.MD`) addresses the same file but misses the
  rule. Case-fold both rule and candidate (and, cheap win, compare the realpath basename).
  *Test:* `Write TRACKER.MD` on the case-insensitive host ⇒ denied in `controlled`.

- **B7. Transactional record+auth (no stranded record)** (Major 5). `idc_command_entry_gate.py`
  `_ensure_path_gate_auth` swallows the exception and, on failure, blocks *after* the command record
  was opened → the stop-closeout gate then nags forever. Abort/close the just-opened record before
  `_block(AUTH_WRITE_FAILED_REASON)`, and stop discarding the underlying exception (log a scrubbed
  reason).
  *Test:* force `write_authorization` to raise ⇒ assert no active record remains for that session.

- **B8. Refuse shared/global `core.hooksPath`** (Major 6). `install_hooks` trusts
  `git rev-parse --git-path hooks/...`, which honors a machine-global `core.hooksPath` and would
  rewrite hooks for unrelated repos. Detect when the resolved hooks dir is outside the repo's own
  `.git` and **refuse with a clear message** (or write a repo-specific dispatcher). Confirmed on this
  machine: setting `core.hooksPath` redirects the resolved path.
  *Test:* set `core.hooksPath` to a shared dir ⇒ `install-hooks` exits non-zero without writing there.

- **B9. Atomic hook install + rollback** (Major 9). `install_hooks` moves the existing hook, then
  does a non-atomic write; an interruption strands the original as only the backup. Write the managed
  hook to a temp file + `os.replace`; on retry, recover the existing `.idc-path-gate-original` backup
  instead of erroring.

- **B10. Pi Edit ≠ Write** (Major 2). `enforceSharedPathGatePath` always sends `action:"write"`.
  Thread the real action so edit-only / write-only grants are honored.

- **B11. Non-Git governed repos** (Major 10). `idc_interlock_gate.py` Write/Edit path hard-denies
  when worktree detection fails, and the new `commands/init.md` authorize step needs a branch. In
  `off` this is moot (observe). In `controlled`, either skip git-bound checks for non-git repos
  (path-only auth) or document non-git as unsupported under `controlled`. Pick the skip; add a test.

- **B12. Minors/Nit.** Minor 1: `authorize` CLI flags default to `None` (not `[]`) so the default
  profile applies. Minor 2: distinguish absent vs unreadable/corrupt auth in the denial text. Minor 3:
  narrow the opaque rule so read-only `find -exec grep` and outside-repo interpreter one-liners aren't
  denied (apply B5 jurisdiction before the opaque check). Nit: delete the unreachable `rc` check under
  `set -e` in `_managed_content`; add the trailing newline to `path-gate-boundaries.sh`.

- **B13. Transport-coverage honesty** (Major 11). Add `NotebookEdit` (and, if cheap, the MCP
  filesystem writer names) to `hooks/hooks.json`, OR document the exact covered-tool boundary in the
  hooks description + WORKFLOW docs. At minimum: no silent gap — say what is and isn't gated.
